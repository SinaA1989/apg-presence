# Contributing to APG

**Bring a statement, a method and a result.**

For the algebra, use the [independent review invitation](https://github.com/SinaA1989/apg-presence/issues/15). For another defect, open a focused issue describing the affected commit, file, expected result, actual result and reproduction command. A counterexample or correction is a useful contribution. Identify AI assistance when it materially contributed to a review; responsibility for checking the result remains with the reviewer.

## Reproduce before changing

Use Node.js 22 and the [reproduction guide](REPRODUCIBILITY.md). Keep Omega v0.1 tests distinct from v0.2 tests. For verifier changes, include cases where evidence is missing, malformed, contradictory or from the wrong account/network/transaction. Never turn UNKNOWN into a positive verification merely to obtain a green check.

Use a branch and pull request, with a short statement of what changed and what was tested. Review code and documentation together. A successful CI run is not an independent security audit or peer review.

## Respect the evidence boundary

Public author: NULL. Artistic signature: ∴. Preserve exact historical signed messages and their provenance. Do not publish private keys, recovery phrases, personal screenshots, unsolicited private contact details or unrelated personal data. Tests use public test-only keys. Documentation work requires no wallet transaction, approval or delegation.

A report about key exposure should omit the secret itself. Do not post exploit instructions against a live account as part of a documentation review.
