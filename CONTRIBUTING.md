# Contributing to APG Ω

Independent criticism and replication are welcome. This repository is a research record, not an investment solicitation.

## Evidence-first contribution format

1. **Claim ID and exact statement:** one falsifiable assertion per issue.
2. **Source:** public URL, repository commit SHA or on-chain contract/transaction.
3. **Chain and state:** chain ID, block number/hash, UTC timestamp, contract address, ABI/function and arguments where applicable.
4. **Procedure:** minimal steps, software version and RPC/endpoint used.
5. **Result:** raw return value or receipt/logs and decoded interpretation; distinguish observation from inference.
6. **Counterexamples and limitations:** what would refute the claim, and what remains unknown.
7. **Proposed change:** correction to a named document or test, with a rationale.

## Evidence classifications

FACT / REPORTED / INFERENCE / UNKNOWN / REFUTED. Do not promote REPORTED to FACT without independent reproducibility. A successful CI check is not proof of a live wallet signature or economic payment.

## Safety and privacy

- Never submit private keys, seed phrases, authentication tokens, passwords or identifying information.
- Never request wallet signatures, approvals, delegations, swaps or on-chain transfers to participate in documentation review.
- Do not claim to control an address without independently verifiable evidence.
- Treat token economics, market valuations and wallet attribution as unverified unless proved from specific state changes.
- Report suspected security issues without publishing exploitable secrets.

## Review standard

A change is ready when it is sourced, falsifiable, internally consistent, reproducible and honest about uncertainty. Preserve the original record; use corrections and dated addenda rather than silently rewriting historical evidence.
