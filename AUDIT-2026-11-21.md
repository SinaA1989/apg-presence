## Scope

Inspected the repository file inventory, executable scripts, tests, workflow, manifests, mathematical definitions, evidence descriptions and relative Markdown links. No AGENTS.md was present in the inspected repository. Existing signed-message references and historical evidence remain historical. No separate GitBook source was supplied or audited.

## Findings and fixes

| Finding | Impact | Correction |
|---|---|---|
| Transfer matches could receive FACT despite wrong chain, transaction identity or failed execution | A per-record result could overstate the evidence even when the aggregate verdict failed | Require all receipt-context checks before certifying transfer claims |
| Missing logs were treated like an empty collection; malformed ABI encodings were loosely decoded | Incomplete evidence could be called REFUTED, or malformed data could match | Missing/malformed/removed log collections become UNKNOWN; require 32-byte data, exactly three topics and zero-padded address words for relevant Transfer events |
| Missing transaction hash was REFUTED; invalid status values were treated as contradictory | Absence and contradiction were conflated | Missing/invalid fields become UNKNOWN; explicit failed status remains REFUTED |
| UNKNOWN returned a successful CLI exit | Automation could mistake incomplete evidence for a positive result | Exit 2 for UNKNOWN, 1 for REFUTED/execution error, 0 for bounded consistency |
| Live RPC calls had no explicit deadline; output did not distinguish fixture mode | Hanging checks and confusion over freshness | 15-second per-request timeout; mode and observation timestamp in output |
| Presence regex could accept an extra final line terminator when that altered text was signed | Canonical-message boundary was less strict than documented | Require the match to consume the entire signed message; retain exact bytes without normalization |
| Claim registers pointed only to v0.1 tests after the v0.2 publication | Readers could confuse two different algebra tables | Identify both versions and their separate tests |
| Navigation and readiness counts were scattered or stale | Readers could miss the authoritative document or infer current status from a historical snapshot | Add an English reference index, contribution guide and historical-ledger notice; remove hard-coded test count from readiness summary |

## Open boundaries

- A verifier trusts its supplied evidence and the selected RPC source; no Merkle proof, consensus verification, RPC independence or log-completeness proof is implemented here.
- Token decimals are declared in the claims file; this receipt check matches base units and does not independently verify decimals or current ownership.
- Presence does not implement ERC-1271, nonce-use tracking, independent signing timestamps or full manifest-field binding. It is not a production authentication protocol.
- The v0.2 algebra is C3; novelty, scientific impact, consciousness and universal physical significance are not established.
- Incoming transfer, net income, ownership, current balance, liquidity and spendability remain different claims.
- Legal licensing, archival retention and a DOI are not created by this audit. Public visibility and Git history do not guarantee permanence or priority.
